The Red Queen Gödel Machine

A recursive self-improvement framework where AI agents and their evaluators co-evolve together — instead of agents improving against a fixed, static benchmark that never changes.

§1 · Motivation
Why Static Evaluation Breaks Down
♛ Named after the Red Queen hypothesis (Van Valen, 1973): species must continuously adapt not toward an absolute ideal, but relative to co-evolving competitors. Staying still means falling behind.

⚠ Current Approach — Static Evaluation

Prior Gödel Machines (DGM, HGM, HyperAgents) use a fixed external evaluator — a benchmark, labeled dataset, or verifier — held constant outside the improvement loop throughout every run.

✓ RQGM — Co-Evolving Evaluation

The Red Queen Gödel Machine treats the utility signal itself as part of the search process. Evaluators improve alongside the agents they score, opening search to evolving objectives.

Three situations where static evaluation fails:

No Benchmark Exists

Paper writing, proof writing — where quality cannot be automatically verified by executing code or looking up answers.

Slow / Noisy Evaluation

Multi-turn agent execution is expensive. A learned judge can be a cheaper, complementary surrogate that speeds up search.

Benchmark Saturation

Static benchmarks saturate or become vulnerable to reward hacking as agents improve beyond what the benchmark was designed to test.

01

Multi-Agent Workspace

Each archive node contains K agentic roles: task agent slots (coder, writer, prover) AND evaluator slots (code reviewer, paper reviewer, proof grader). All share a common codebase.

02

Three-Level Sampling

Node → Role → Task. At each level, the scheduler picks the least-evaluated eligible option, ensuring balanced coverage across all roles and tasks. Clade meta-productivity (CMP) drives node selection.

03

Frozen Within Each Epoch

The evaluator is locked ("epoch-stationary") within each epoch. This means within-epoch search is a standard fixed-criterion problem — prior HGM convergence guarantees apply directly.

04

Evolving Across Epochs

At epoch boundaries, challengers compete against the incumbent evaluator on a held-out ground-truth anchor. The ε-best-belief winner is frozen for the next epoch. Selective erasure removes stale records.

§3 · Key Mechanism
Controlled Utility Evolution
⟳ The core insight: run self-improvement with a frozen evaluator (so guarantees hold within each epoch), but allow the evaluator to be upgraded at epoch boundaries if a better one emerges from co-evolution.
Search Timeline
Epoch 0 — Fixed Evaluator E₀

Agents evolve under frozen evaluator E₀. HGM search within epoch. Challenger evaluators co-evolve in parallel.

● Clade utility stable · archive grows
♛ BOUNDARY
E₁ beats E₀ on GT
Epoch 1 — Upgraded Evaluator E₁

Selective erasure removes stale E₀ records. Agents re-ranked under stricter E₁. Utility dips then re-climbs.

● Utility drops → re-climbs under E₁
♛ BOUNDARY
E₂ beats E₁ on GT
Epoch 2 — Stronger Evaluator E₂

Each epoch's evaluator is provably better than the last. Agents now optimized against an increasingly rigorous judge.

● Curriculum effect: ever-harder bar
Selective Erasure

When E₀ is replaced by E₁, only utility records scored by E₀ are discarded. Unrelated task records survive. Amortized re-evaluation cost is O(B) — linear in budget, not O(B²).

Exponential Checkpoints

Epoch boundaries are exponentially spaced (ratio ρ > 1). Later evaluators — which are more accurate — get longer epochs and shape the search for longer. Earlier, weaker evaluators expire cheaply.

Shared Codebase

90% of accepted patches in the coding domain modify shared infrastructure used by both coder and reviewer — a single edit improves both roles.

Curriculum Effect

As evaluators strengthen across epochs, they re-rank the archive — imposing a natural curriculum. Agents must satisfy progressively harder criteria to survive.

Adversarial Regularization

After epoch 0, papers accepted by the displaced reviewer become adversarial negatives. The new reviewer learns to be equally strict on AI and human work.

§6 · Theoretical Guarantees
What RQGM Can Formally Prove
Proposition 3 · Epoch-Local Validity

Per-Epoch Convergence

Each epoch with a frozen evaluator is a fixed-criterion search problem. HGM's convergence guarantees apply directly within every epoch. Selective erasure ensures no cross-epoch utility contamination.

Propositions 4–5 · Anchor Improvement

Cross-Epoch Progress

The promoted evaluator maximizes ε-best-belief on the ground-truth anchor — a lower bound that the anchor utility exceeds with probability 1−ε. So evaluators get provably better across epoch boundaries.

Proposition 6 · Amortized Cost

Linear Recovery Cost

With exponentially spaced checkpoints (ratio ρ > 1), the cumulative records exposed to erasure or re-evaluation is O(B) — linear in budget, reducing from the naive O(B²) that would result from per-step transitions.

Informal Summary

Convergence holds epoch-by-epoch via epoch-local stationarity (Prop. 3). Evaluators improve across epochs via anchor-guided promotion (Rem. 3). Co-evolution adds no asymptotic overhead beyond standard archive search (Prop. 6). The cost is looser convergence guarantees than fully static evaluation — but the benefit is access to open-ended domains that static evaluation cannot handle at all.

§7 · Summary
Three Key Contributions
C1

Non-Stationary Recursive Self-Improvement

Extends self-improving agents beyond fixed external evaluation. The utility signal is itself part of the search process, enabling search objectives to evolve and opening self-improvement to open-ended domains.

C2

Controlled Utility Evolution Mechanism

Makes non-stationary utilities compatible with prior self-improvement guarantees. Fixed-evaluator epochs + boundary-only changes + ε-best-belief promotion = co-evolution with formal per-epoch convergence.

C3

Practical Co-Evolved Evaluator Benefits

Three demonstrated benefits: (i) cheaper complementary coding signal (+1.35–1.72× efficiency), (ii) generator search where no benchmark exists (1.78–1.86× higher paper acceptance), (iii) adversarial debiasing to fix LLM self-preference.

→

Future Vision

A class of self-improving co-evolving systems where agents and evaluators recursively bootstrap one another without further human intervention — a meaningful step toward capable AI with open-ended, evolving objectives. Future work: longer search horizons, SWE-bench, richer co-evolutionary dynamics.
