CatalogAgent
E-Commerce Catalog
Quality Agent

An autonomous data agent that discovers, merges, and validates external product attribute data to close catalog quality gaps — boosting search ranking and conversion without retraining any ranking model.

Status: Draft 3-Month MVP Connects to CatalogLab v0.1 · May 2026
Section 01

Why this exists and what it costs Marketplace Ichiba today.

Root Cause
Catalog Quality Is Manually Gated
Merchant-provided data is the only input. Merchants omit or misclassify attributes because catalog tools are complex and incentives are misaligned. No automated enrichment from external authoritative sources exists today.
Downstream Impact
Search & Ranking Model is Data-Starved
The ranking model is frozen post-deployment. Its performance is now entirely constrained by input data quality. Every missing attribute is a missed ranking signal — and a missed conversion opportunity — invisible to the model.
Key insight from DataMaster paper (arXiv 2605.10906): a fixed model can achieve significant performance gains (+32% on MLE-Bench Lite) through autonomous data pipeline optimization alone. CatalogAgent applies this principle directly: the ranking model does not change — only the data fed to it improves.
Section 02

Solution Overview

CatalogAgent in one sentence: an autonomous agent that hunts external product data, tests each enrichment against the live ranking model, and commits only what measurably improves search score.

Value Proposition
Autonomous Catalog Enrichment with Downstream Score Validation
CatalogAgent runs a continuous loop: discover external product attribute data from open graphs (Open Food Facts, GS1, brand structured data) → merge with existing SKU catalog → score the impact using CatalogLab's frozen quality scorer → commit only enrichments that lift the score. Every decision is traceable via a versioned DataPool manifest.

Section 04

Agent Loop Architecture

The DataMaster loop adapted for catalog enrichment. Red nodes discover. Black nodes evaluate. The DataPool and GlobalMemory persist state across iterations.

Main Loop — UCB-Scheduled Iteration
Trigger
SKU Gap Detection
CatalogLab scorer flags SKUs below quality threshold. Batch queued to agent. Scheduler runs nightly or on new listing events.
UCB node selection
RED NODE
External Data Discovery
Agent queries GS1 GEPIR, Open Food Facts API, Google Merchant structured data, and brand sitemaps using product identifiers (GTIN, JAN, EAN, brand+title). Discovered datasets written to DataPool as versioned manifests with source, schema, and coverage metadata.
batch of 3 black nodes spawned
BLACK NODE
Schema Alignment + Attribute Merge
Each black node picks a manifest from DataPool. Runs schema alignment (Marketplace attribute ontology → external field mapping), conflict resolution (merchant data wins on price/inventory; external wins on physical attributes), and generates a candidate enriched SKU record.
pass to evaluator
BLACK NODE
CatalogLab Downstream Evaluation
Candidate enriched SKU is scored by CatalogLab (frozen scorer). Score delta vs. baseline is computed. Only enrichments with Δ > +2 pts are eligible for promotion. Results backpropagated to DataTree.
winners promoted
Output
Commit + Provenance Write
Enriched SKU record written to production catalog. Full provenance logged: source URL, manifest ID, attribute deltas, scorer delta, timestamp, operator. GlobalMemory updated with category-level enrichment pattern.
Persistent State
DataPool
Enriched SKU Manifests
Key-value store: manifest_id → {source, schema, coverage, score_delta, parquet_path}. Avoids re-crawling sources already proven useful. Cache TTL: 30 days.
GlobalMemory
Category Enrichment Rules
Accumulates: which sources reliably improve which categories, conflict resolution outcomes, attribute fill rates by source. Shared across all parallel runs. Grows in value over time.
DataTree
Search State (NetworkX DiGraph)
Red nodes = discovery branches. Black nodes = eval branches. UCB score = exploit (avg Δ) + explore (log-based). Backpropagation updates parent nodes.
Artifact Store
Parquet + JSON
Every black node writes: enriched_sku_<id>.parquet + provenance_<id>.json. Enables full audit, rollback, and replay.
Section 05

Core Components

Six modules. Each maps to a DataMaster primitive plus catalog-specific logic.

Red Node Engine
ExternalDataDiscoverer
Takes a batch of SKUs with gap flags. Generates lookup queries per SKU using GTIN/JAN/EAN or title+brand+category. Calls configured source adapters in parallel. Writes each discovered dataset as a manifest to DataPool. Deduplicates against existing pool entries.
AsyncConfigurable sourcesRate-limited
Black Node Engine
AttributeMerger
Loads a manifest from DataPool. Runs schema alignment using Marketplace attribute ontology. Applies conflict resolution policy (configurable per attribute class). Outputs candidate enriched SKU as a Pydantic model. Tracks every field delta for provenance.
Policy-drivenSchema-aware
Evaluation
CatalogLabScorer (Frozen)
Thin wrapper around the existing CatalogLab quality scoring API. Takes a candidate SKU record, returns a quality score 0–100. Computes delta vs. baseline score for that SKU. This is the only "model" in the system — and it never changes.
Frozen scorerREST API

ManifestStore
Redis-backed (or Postgres JSONB for MVP). Key: manifest_id. Value: source metadata + score_delta + schema fingerprint + parquet path + TTL. Candidate selection uses relevance score: category match × source reliability × recency weight.
VersionedCache-firstTTL-aware
GlobalMemory
CategoryInsightStore
Append-only log of enrichment outcomes keyed by (category_L2, source). Surfaces: best sources per category, conflict resolution history, attribute fill rates by source. Used by ExternalDataDiscoverer for smarter query targeting.

External Data Sources

Red nodes target these sources. Each has a registered adapter in the ExternalDataDiscoverer.

Source Lookup Method Attributes Covered Category Fit Reliability MVP
GS1 GEPIR GTIN / EAN / JAN lookup Brand, pack size, net weight, country of origin, product description All physical goods High — authoritative registry ✓ MVP
Open Food Facts EAN barcode → REST API Ingredients, allergens, nutrition facts, labels, packaging, categories Food, Beverage, Health High — community + brand submissions ✓ MVP
Google Merchant Structured Data Brand site sitemap + schema.org/Product JSON-LD Color, size, material, description, MPN, images, age group Apparel, Electronics, Home Medium — depends on brand site quality ✓ MVP
Open Product Data (Akeneo) GTIN / product name REST search Technical specs, dimensions, certifications, compatibility Electronics, Industrial Medium Phase 2
Wikidata SPARQL: brand + product name → entity Country of origin, founding year, parent company, product class Brands, Books, Media Medium — crowd-sourced Phase 2
Open Library / ISBN DB ISBN-13 lookup Author, publisher, edition, genre, subject, page count, language Books High Phase 2
Marketplace Global Catalog (internal) JAN code cross-reference via internal API All attributes from other Marketplace market catalog records All categories High — internal authority Phase 3
Conflict resolution policy (default): Merchant data wins on price, inventory, and primary image. External authoritative sources (GS1, Open Food Facts) win on physical attributes (weight, dimensions, ingredients, materials). Brand site structured data fills gaps only — never overwrites existing values. Policy is configurable per category and per attribute class.
Section 07

API Contract

FastAPI service. Three primary endpoints for the MVP. All responses include provenance.

POST /enrich
Trigger Enrichment Job
Submit a batch of SKU IDs (or quality filter). Returns job_id. Async — job runs in background via Celery/ARQ.
GET /job/{job_id}
Job Status + Results
Returns status, skus_processed, skus_enriched, avg_score_delta, manifest_ids committed. Includes link to provenance artifact.
GET /pool
DataPool Manifest Browser
Paginated list of manifests. Filterable by category, source, score_delta range, date range. Powers the enrichment insights dashboard.
POST /rollback
Revert Enrichment
Takes manifest_id or sku_id. Reverts enriched attributes to pre-enrichment state using stored provenance artifact. Required for operator trust.
POST /enrich
{
  "sku_ids": ["RAK-12345", "RAK-67890"],   // explicit list, OR...
  "quality_filter": { "max_score": 65 },   // ...filter by score
  "categories": ["food_beverage"],         // optional scope
  "sources": ["gtin_gs1", "open_food_facts"],
  "min_delta_threshold": 2,               // only commit Δ ≥ 2 pts

}

Section 10

System Integrations

CatalogLab
Quality Scorer (downstream evaluator)
CatalogLab is the frozen evaluation oracle. CatalogAgent calls POST /score with a candidate SKU before any write. Score delta gates commit decisions. No changes to CatalogLab required for MVP.
Discover → Design → Convert
CatalogAgent maps to the Discover stage of . Red nodes = Discover, black nodes = Design + Convert. Operates output flows into the Validate → Operate stages via the existing event bus.
Marketplace SKU Store
Read (base data) + Write (enriched data)
Agent reads current SKU attributes as baseline. Writes enriched record back via PATCH /catalog/sku/{id} with X-Enrichment-Source: catalog-agent header for audit trail separation from merchant updates.
Observability
OpenTelemetry + Grafana
Traces: one span per SKU enrichment with attributes (source, delta, commit/reject decision). Metrics: enrichment throughput, pool hit rate, source reliability, score delta distribution. Alerts on enrichment precision below threshold.
Integration decision: CatalogAgent does NOT integrate with the ranking model directly. It only improves the data that feeds it. This is the core DataMaster insight — and it keeps the architecture boundary clean.

Section 13

Open Questions

Decisions that must be made before Month 1 kickoff. Owner and deadline assigned.

Blocker — Decide by Week 1
CatalogLab API Access Mode
Does CatalogAgent call CatalogLab via internal HTTP (same VPC) or does CatalogLab expose a batch scoring endpoint? Batch scoring needed for throughput — confirm with CatalogLab engineering before sprint planning.
Blocker — Decide by Week 1
SKU Store Write Permissions
CatalogAgent needs a service account with write access to the production SKU attribute store. Requires InfoSec review. Separate write path with X-Enrichment-Source header — confirm schema change with Platform team.
Decide by Month 1 End
Minimum Delta Threshold Calibration
Default is Δ ≥ 2 pts on CatalogLab score. Is this the right gate? Need to calibrate against historical enrichment data — what delta corresponds to measurable search rank lift? Requires joint analysis with CatalogLab team.
Decide by Month 1 End
DataPool Storage Backend
MVP: Redis HASH + Postgres JSONB fallback. Phase 2: Consider ArangoDB (already in ) for richer graph queries on source-category relationships. Confirm with infra team if ArangoDB instance can be shared.
Decide by Month 2
Merchant Notification Strategy
Do we notify merchants when their SKU is auto-enriched? Options: silent (ops-only), notification only, approval-required for high-value SKUs. Phase 3 design decision — but policies should be set early to avoid merchant trust issues.
Decide by Month 2
A/B Experiment Design
Holdout cohort: matched on category, price band, and current quality score. Primary metric: add-to-cart rate at 4 weeks. Secondary: search position. Confirm with Data Science team on experiment sizing and contamination risk.
