Superintelligent Retrieval Agent (SIRA) Practical Hands-On Tutorial** **** This is a **complete, production-oriented, step-by-step tutorial** to implement the core of Meta’s SIRA paper (arXiv:2605.06647, released May 2026) in a **real-world enterprise use case**. ### Real-World Use Case: Internal Company Knowledge-Base Search (RAG without Vector DBs) **Problem**: Your company has 1,000–100,000+ internal documents (policies, engineering specs, research notes, Slack archives, Notion pages exported to text). Traditional BM25 misses vocabulary gaps. Dense retrievers (e.g., E5, Voyage) are expensive, slow, and opaque. Multi-turn agentic search is high-latency. **SIRA Solution** (exactly as in the paper): - **Offline** (once): LLM enriches every document with *discriminative vocabulary* (synonyms, aliases, jargon a user would actually search) that is **absent** from the original text. - **Online** (per query): LLM generates an “expected-response sketch” → validates terms via document-frequency (DF) statistics → compiles one weighted BM25 query. - Result: **One-shot retrieval** that beats dense models and multi-round agents on BEIR-style tasks while being 10–30× cheaper and fully interpretable. You will end up with a **search function** that you can plug directly into LangChain, LlamaIndex, Haystack, or a FastAPI backend. ### Why This Is Production-Ready  Zero training / no relevance labels. - Pure sparse (inverted index only) → sub-10 ms latency even on 100k docs. - Fully auditable (you can see exactly which enriched terms fired). - Scales to millions of docs with Whoosh / Elasticsearch later. - Matches the paper’s “compress multi-round search into a single BM25 call”. ### Prerequisites ```bash pip install rank-bm25 tqdm datasets ollama # Optional for production later: whoosh or elasticsearch ``` - **LLM**: Ollama (recommended for privacy & zero cost). Run: ```bash ollama pull qwen2.5:14b # or llama3.3:70b, mistral-nemo, etc. Paper used ~35B-class ollama serve ``` - Python 3.10+ - ~8–16 GB RAM (fine for 10k+ docs) ### Step 1: Load or Create Your Corpus We’ll use a small real BEIR dataset for immediate reproducibility, then show how to swap in your own documents. ```python from datasets import load_dataset import re from tqdm import tqdm # Real-world: replace with your own folder of .txt / .md files dataset = load_dataset("BeIR/scifact", "corpus", split="train") corpus = [doc["text"] for doc in dataset] # ~5k scientific abstracts – perfect demo size # Optional: your own data # def load_from_folder(folder_path): # docs = [] # for file in Path(folder_path).glob("*.txt"): # docs.append(file.read_text()) # return docs # corpus = load_from_folder("knowledge_base/") print(f"Loaded {len(corpus)} documents") ``` ### Step 2: Offline Corpus Enrichment (Amortized, Run Once) This is the **secret sauce** from the paper: LLM injects missing search vocabulary. ```python import ollama def get_llm_response(prompt: str, model: str = "qwen2.5:14b") -> str: response = ollama.chat(model=model, messages=[{"role": "user", "content": prompt}]) return response['message']['content'].strip() # Prompt (derived directly from paper description) CORPUS_ENRICHMENT_PROMPT = """You are an expert document indexer for a corporate knowledge base. Given the document below, generate 8-12 NEW discriminative search terms/phrases (synonyms, aliases, domain jargon, abbreviations, alternative phrasings) that a user might search for to retrieve this document BUT THAT DO NOT APPEAR anywhere in the document text. Focus on terms that would maximize lexical contrast with other documents. Output ONLY a comma-separated list. No explanations. Document: {document} """ def enrich_document(doc_text: str, tau: float = 0.01) -> str: # Step 2.1: Ask LLM for new terms prompt = CORPUS_ENRICHMENT_PROMPT.format(document=doc_text[:8000]) # truncate if needed raw_terms = get_llm_response(prompt) new_terms = [t.strip() for t in raw_terms.split(",") if t.strip()] # Step 2.2: DF validation (for corpus-side: no lower bound, only upper) # We will compute full DF after all enrichments, but for simplicity we skip heavy upper-bound pruning here # (new terms have DF=0 initially → they always pass) # Append as space-separated (paper uses n-grams; we keep simple for demo) enriched = doc_text + " " + " ".join(new_terms) return enriched print("Starting offline corpus enrichment (this takes time but runs once)...") enriched_corpus = [] for doc in tqdm(corpus[:500]): # start with 500 for fast iteration enriched_corpus.append(enrich_document(doc)) print("Corpus enrichment complete!") ``` **Production tip**: Run this once on a GPU instance or batch job. Cache the enriched texts. ### Step 3: Build DF Statistics & BM25 Index on Enriched Corpus ```python from rank_bm25 import BM25Okapi from collections import Counter import nltk nltk.download('punkt', quiet=True) from nltk.tokenize import word_tokenize def simple_tokenize(text): # Consistent tokenization (paper uses Lucene-style; this is close enough) return [t.lower() for t in word_tokenize(text) if len(t) > 2] # Build final DF for validation (used in query stage) all_tokens = [] tokenized_enriched = [] for doc in enriched_corpus: tokens = simple_tokenize(doc) tokenized_enriched.append(tokens) all_tokens.extend(tokens) df_counter = Counter(all_tokens) N = len(enriched_corpus) print(f"Corpus size: {N} | Unique terms: {len(df_counter)}") # Build BM25 index (on tokenized enriched docs) bm25 = BM25Okapi(tokenized_enriched) ``` ### Step 4: Online Query Enrichment + Weighted BM25 Retrieval (The One-Shot Magic) ```python QUERY_ENRICHMENT_PROMPT = """You are a domain expert retrieval controller. Given the user query below, generate an "expected-response sketch": 8-12 key concepts, entities, and discriminative terms/phrases that are LIKELY to appear in relevant documents BUT ARE MISSING from the original query. Do NOT guess the actual answer. Focus on vocabulary gaps that would help narrow the search. Output ONLY a comma-separated list. Query: {query} """ def sira_retrieve(query: str, top_k: int = 10, w: float = 1.5, tau: float = 0.01): # Step 4.1: Generate expected-response sketch prompt = QUERY_ENRICHMENT_PROMPT.format(query=query) raw_exp = get_llm_response(prompt) exp_terms = [t.strip().lower() for t in raw_exp.split(",") if t.strip()] # Step 4.2: DF validation (paper's exact filter) validated_exp = [] for term in exp_terms: df = df_counter.get(term, 0) if df > 0 and df <= tau * N: # must exist + not too common validated_exp.append(term) # Step 4.3: Tokenize queries q_orig_tokens = simple_tokenize(query) q_exp_tokens = validated_exp # already lower-cased tokens # Step 4.4: Weighted BM25 (exact formula from paper) scores_orig = bm25.get_scores(q_orig_tokens) scores_exp = bm25.get_scores(q_exp_tokens) if q_exp_tokens else [0.0] * len(scores_orig) final_scores = [s1 + w * s2 for s1, s2 in zip(scores_orig, scores_exp)] # Rank ranked = sorted(enumerate(final_scores), key=lambda x: x[1], reverse=True)[:top_k] results = [] for idx, score in ranked: results.append({ "doc_id": idx, "score": round(score, 4), "text": corpus[idx][:300] + "...", # original text for display "enriched_terms_matched": [t for t in q_exp_tokens if t in tokenized_enriched[idx]] }) return results # Demo query = "How does retrieval-augmented generation improve factual accuracy?" results = sira_retrieve(query, top_k=5, w=1.5) for r in results: print(f"Score: {r['score']} | Matched terms: {r['enriched_terms_matched']}") print(r['text'][:200] + "\n") ``` ### Step 5: Evaluation & Ablation :  Add this to compare: -
